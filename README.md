
# CsModular

A web-based modular synthesizer built with Csound and vanilla JavaScript + Canvas.

This project is a next level of the *pch2csd* project: https://github.com/gleb812/pch2csd

## Features

- Modular architecture with interchangeable audio modules
- Real-time Csound synthesis engine (via `@csound/browser`)
- MIDI input via Web MIDI API — browser → `MidiManager` → Csound (`instr 3` NM2-compatible gate/note filter)
- Web-based UI with Canvas rendering
- Runs as a web app (browser) or desktop app (Tauri: Windows / Linux / macOS)
- Infinite workspace with pan, zoom and scroll
- Voice / FX layers — modules can be assigned to either, with auto-layout for FX
- Grid system with configurable step (X/Y multipliers) and snap-to-grid
- Two visual themes:
  - Classic — original NM2-style colored UI
  - LCD — monochrome glowing interface inspired by Casio watches
- Design Settings panel (press `D`) — live theme editing, color pickers, glow, line weight, cable widths, background, grid
- Oscilloscope — multi-channel waveform viewer for any cable (audio or control), opened via right-click on a jack → **Send to Scope**
- Custom backgrounds — solid colors or images, with parallax effect
- Module Editor — built-in IDE-style editor with dock panels and command terminal
- Protected code structure — `opcode` / `xin` / `zar` / `zkr` / `init` / `zaw` / `zkw` / `endop` are locked (🔒) and regenerated from the module model; the user only edits the DSP body
- User modules stored as plain files (in Tauri) — easy to back up, share, version

## Architecture

- Frontend: vanilla JS (ES modules), Vite
- Audio: `@csound/browser` 7.0.0-beta33
- MIDI: Web MIDI API → `src/midi/MidiManager.js` → `CsoundEngine.midiMessage()` → Csound `instr 3`
- Desktop shell: Tauri 2.x (Rust)
- Storage:
  - Web: localStorage (`moduleStore.web.js`)
  - Desktop: filesystem via `@tauri-apps/plugin-fs` (`moduleStore.tauri.js`)
  - Abstraction: `src/api/index.js` — lazy `moduleStore` singleton
- UDO loading:
  - User modules (`user/<Name>.txt`) — via `moduleStore` (web: localStorage, Tauri: fs)
  - Built-in modules (`<id>.txt`, `led_rms.txt`) — via `fetch` from `public/csound/modules/`, with HTML-fallback detection
  - Single entry point: `CsoundGenerator._loadUdoByPath()`
- Theme system: `src/theme/` (`Theme.js`, `themeStore.js`, `currentTheme.js`, `defaults.js`)
- Grid system: `src/grid/Grid.js`
- Csound code: UDO files in `public/csound/modules/*.txt`
- Oscilloscope: `src/ui/ScopeWindow.js` — reads Csound f-tables via `tableCopyOut()` polling; ring-buffers are generated by `CsoundGenerator._generateScopeCode()`
- Scripts: Python patchers in `scripts/` (params, mapping tables, NM2 cleanup)

## Voice / FX layers

Every module belongs to one of two layers:

- Voice — triggered per polyphony voice (default)
- FX — global effects, master processing

Rules:
- Cables are only allowed within one layer (voice ↔ voice, fx ↔ fx)
- Change layer via right-click → Layer → Voice / FX
- When changing layer, all cables are removed (with confirmation)
- New FX modules are automatically placed below the lowest voice module

## Grid

The world is infinite, with a configurable grid:

- Base cell 20×15 px, panel always 13 cells wide (= 260 px, NM2 compatibility)
- Step multipliers `multX` / `multY` (≥ 1) — configurable in Design Settings → Grid
- Visible as crosses (not lines), style depends on theme
- Snap to grid can be toggled on/off
- Changing multipliers does not move existing modules — only the next drag uses the new step
- Grid settings persist in localStorage as part of the theme (`settings.grid`)

## MIDI

MIDI input is received in the browser via the **Web MIDI API** and forwarded
to Csound through `CsoundEngine.midiMessage()`. On the Csound side,
`instr 3` acts as an NM2-compatible MIDI filter: it reads `midiin`, and
exposes `gkGate` / `gkNote` for the rest of the patch.

## Oscilloscope

A multi-channel waveform viewer for debugging the patch. It is **not** a
module — it lives in a separate overlay window and is bound to **cables**
(ZAK buses), not to modules.

### How to open

1. Connect two modules with a cable.
2. Right-click on either jack of the cable → **📊 Send to Scope**.
3. The oscilloscope window opens with the new channel.

Each cable becomes one channel. Up to **8 channels** per window.

### Signal chain

Cable (ZAK bus)
→ CsoundGenerator.addScopeTable(cable)
→ giScope_<N> ftgen <N>, 0, 4096, 2, 0
→ in instr 1/2:
kScopeIdx_<N> phasor (sr / ksmps) / 4096
aScopeSig_<N> zar <bus> ; or kScopeSig_<N> zkr <bus>
tablew aScopeSig_<N>, aScopeIdx_<N>, <N>, 1
→ CsoundEngine.registerScopeTable(cableId, tableNum)
→ polling 30 Hz: instance.tableCopyOut(tableNum) → Float64Array
→ ScopeWindow reads CsoundEngine.getScopeBuffer(cableId) each frame

### How it works

- **Ring buffer** — a 4096-sample `ftgen` per scoped cable. `phasor` at
  `(sr / ksmps) / 4096` Hz writes a normalized 0..1 index; `tablew` with
  `ixmode=1` maps it to the table.
- **Audio cables** — `zar <bus>` reads the audio-rate signal; `tablew` writes
  every sample (`aScopeIdx` is a-rate).
- **Control cables** — `zkr <bus>` reads the control-rate signal;
  `k(aScopeIdx)` converts the a-rate index to k-rate for `tablew` (Csound
  requires matching types for signal and index).
- **Reading** — `CsoundEngine` polls `tableCopyOut(tableNum)` every 33 ms
  (~30 Hz) and caches the result. `ScopeWindow` reads the cached buffer in
  `requestAnimationFrame`.
- **Trigger** — zero-crossing (rising edge through `triggerLevel`) on the JS
  side; the waveform does not "drift" for periodic signals.

### Controls

| Control | What it does |
|---|---|
| `Time/div` | Number of samples shown (64..4096) |
| `Volt/div` | Vertical gain (0.1..10) |
| `Offset` | Vertical offset (-1..1) |
| `Trigger` | Enable/disable zero-crossing trigger |

Channel chips in the header toggle visibility and can be removed with `✕`.

### Limitations

- **Buffer size** — 4096 samples ≈ 85 ms at 48 kHz. Fine for audio-rate
  waveforms; too short for very slow LFOs (< 1 Hz). Increase `ftgen` size and
  `phasor` frequency in `_generateScopeCode()` if needed.
- **Control cables** — the signal is sampled at k-rate, so the waveform is
  effectively downsampled by `ksmps`. This is visually fine for LFOs and
  envelopes.
- **CPU** — `tablew` runs in audio-rate for every scoped cable. Practical for
  ~4–8 channels; more may affect real-time performance.
- **Recompile required** — adding a scope channel calls `_recompileDebounced()`
  because `ftgen` + `tablew` only appear in the ORC after regeneration.
- **Not persisted** — scope channels are not saved in the patch JSON. They are
  a debugging tool, not part of the patch.

```
MIDI device → Web MIDI API (browser)
            → MidiManager.onMessage (src/midi/MidiManager.js)
            → CsoundEngine.midiMessage(status, data1, data2)
            → Csound `instr 3` (midiin)
            → gkGate / gkNote
```

### Enabling MIDI

1. Click the **`MI`** button in the bottom bar.
2. Grant the browser permission when prompted.
3. The button lights up and flashes on every incoming MIDI message.

### Requirements

- **Secure context** — `https://` or `http://localhost`
- **Browser support** — Chrome / Edge / Firefox (Web MIDI is not available in Safari on all platforms)
- **Linux** — Chrome/Firefox receive MIDI through **ALSA sequencer**; the device must be visible in `aconnect -i -o`
- **Tauri** — Web MIDI support depends on the platform WebView (WebView2 on Windows, WKWebView on macOS). On macOS, Web MIDI is not exposed by WKWebView out of the box and may require a plugin or Rust-side MIDI.

### What's implemented

- Note On / Note Off (`0x90` / `0x80`) → `gkGate`, `gkNote` (velocity is currently ignored — NM2 compatibility)
- Any other MIDI message is forwarded to Csound as-is (CC, pitch bend, etc. — available for future use)
- Last 50 messages are stored in `MidiManager.history` (for debugging)
- MIDI status is shown in the SysInfo popup (`i` button)

### Known issue: MIDI stops working after recompile

After `recompile()` (`reset` + `compileOrc`), MIDI events stop reaching
Csound, and a subsequent `stop()` → `init()` may throw:

```
TypeError: can't access property "csoundMainRtMidiPort",
this.ipcMessagePorts is undefined
```

This is an internal `@csound/browser` issue (IPC message ports are not
recreated after `reset()`). It is **not** caused by the project code.
Workarounds under investigation:

- try a different `@csound/browser` version (`7.0.0-beta*` or older `6.18.5`)
- avoid `reset()` + `compileOrc` in favour of a full restart (slower — rejected for now)
- re-initialize MIDI ports after recompile, if the API allows it

### Debugging

- Browser console: `[MidiManager]` logs for access state, device connect/disconnect
- `CsoundEngine.midiMessage()` returns `false` and logs a warning if the Csound instance does not expose `midiMessage()`
- In Csound, `printk` inside `instr 3` shows the raw MIDI status (temporary debug aid)

## Module Editor

The editor is a separate HTML entry (`editor.html`) that opens in its own window
(in Tauri) or tab (web). It provides an IDE-style workspace for designing
custom modules visually.

### Layout

The editor uses a fixed dock layout with resizable splitters and presets
(`Default`, `Code`, `Canvas`). All panel sizes persist in `localStorage`.

```
┌─────────────────────────────────────────────────┐
│ toolbar: [New] [Load] [Save]  |  Layout presets │
├──────────────────────┬──────────────────────────┤
│                      │                          │
│   Canvas (module)    │   Csound Code            │
│                      │                          │
├──────────────────────┼──────────────────────────┤
│                      │                          │
│   Properties         │   Terminal               │
│   (Module/Component) │   (command language)     │
│                      │                          │
└──────────────────────┴──────────────────────────┘
```

- Canvas — visual module layout, drag components, resize module
- Properties — two tabs: `Module` (name, height, color) and `Component`
  (schema-driven fields from `getPropertySchema()`)
- Csound Code — live-generated `opcode` code with syntax highlighting,
  line numbers, font size controls, **protected structure** (see below)
- Terminal — command language for the module (see below)

### Protected Csound code structure

The Csound Code panel is split into three zones by the generator:

- **Header (🔒 protected)** — `;@ map`, `opcode`, `xin`, mapping table lines
- **Body (editable)** — your DSP code, between the input-jack block and the output-jack block
- **Footer (🔒 protected)** — `zar/zkr/init` and `zaw/zkw` lines, `endop`

What you can and can't do:

- The protected lines are **regenerated from the module model** whenever you
  add/remove components, rename the module, or change mappings.
- The cursor cannot enter protected lines. Backspace at the start of the body
  stops at the upper boundary; Enter at the end of the body inserts new lines
  (the footer shifts down).
- Structural keywords (`zar`, `zkr`, `zaw`, `zkw`, `xin`, `opcode`, `endop`)
  are **forbidden inside the body** — the editor blocks input and highlights
  any leftovers in red.
- Clicking `⟳` (Sync) regenerates the whole code from the model — the body
  is reset to the placeholder.

### Adding components

Right-click on the canvas → Add Component → pick from submenu
(Controls / Display / Jacks / Graphics).

All components live in `editor/ComponentRegistry.js` — a single source of
truth describing how each component is created, serialized, deserialized,
and what Csound ports it has. Adding a new component type = adding one
entry to the registry.

### Editable component properties

Component fields are declared via `static getPropertySchema()` in the
component class and rendered by `PropertiesPanel`. Supported field types:

| Type | UI | Example |
|---|---|---|
| `text` | text input | `TextLabel.text`, `ButtonText.text` |
| `number` | numeric input (min/max/step) | `Knob.min`, `ButtonRadio.buttonCount` |
| `list` | comma-separated input → array | `ButtonFlat.positions`, `ButtonIncDec.items` |
| `checkbox` | toggle | `ButtonText.isActive` |
| `select` | dropdown (`options` / `optionsFrom`) | `TextField.format` |
| `mapping-select` | custom field + 🔍 table browser | `Knob.mappingTable` |

Schemas can define an `afterChange(comp, value)` callback to run
post-update logic (clamp indices, rebuild labels, update `width` for
`ButtonRadio` after changing `buttonCount`, etc.).

Currently editable:

- **Knob** — `mappingTable`
- **Slider** — `mappingTable`
- **TextLabel** — `text`, `fontSize`, `color`
- **ButtonFlat** — `positions`, `currentIndex`
- **ButtonRadio** — `labels`, `buttonCount`, `selectedIndex`
- **ButtonIncDec** — `items`, `currentIndex`
- **ButtonText** — `text`, `isActive`

`mappingTable` is only supported on `Knob` and `Slider` for now.

### Saving & loading

- Web: modules persist in `localStorage` under
  `csmodular:user_modules` (list) and `csmodular:user_module:<name>` (data)
- Tauri: modules are written to
  `~/Documents/CsModular/modules/user/<name>.js` and
  `~/Documents/CsModular/csound/modules/user/<name>.txt`

Both JS and DSP code are stored. Round-trip load/save preserves the module
as designed, including:

- `mappingTable` on `Knob` and `Slider`
- Multi-position labels on `ButtonFlat` / `ButtonRadio` / `ButtonIncDec`
- Default index/state on all button-like components
- `TextLabel` text, font size, color

Loading a module restores the DSP body and rebuilds the protected structure
around it (`restoreModuleFromData` → `_rebuildStructure()` +
`_rebuildStructureFromCurrent()`).

## Troubleshooting

Csound WASM not loading:
- Check browser console for errors
- Ensure `@csound/browser` is accessible (CDN or bundled)

Tauri build fails:
- On Windows: install Microsoft C++ Build Tools
- Install WebView2 Runtime (Windows 10)
- Ensure `rustc --version` works

Port 3000 already in use:
- Kill the process, or change port in `vite.config.js`

Background not changing:
- Check DevTools Console for errors
- Ensure theme has `background` section — reset via `localStorage.removeItem('csmodular.theme')`

User modules not visible in browser:
- Web `moduleStore` uses `localStorage`
- Check DevTools → Application → Local Storage → `csmodular:user_modules`
- To reset: `localStorage.removeItem('csmodular:user_modules')`

**HTML inside Csound ORC** (`<!DOCTYPE html>` after `endop`):
- Cause: `fetch('/csound/modules/<path>')` returns Vite SPA-fallback `index.html`
  for missing files, and the response status is 200 (so `response.ok === true`)
- Fixed: all UDO loading goes through `CsoundGenerator._loadUdoByPath()`, which
  routes `user/*` through `moduleStore` and detects HTML for built-in paths
- If it happens again, check the console for `⚠️ Got HTML instead of UDO for …`

**LED / oscilloscope behave erratically after loading a module**:
- Cause: `mappingTable` on `Knob`/`Slider` was not serialized, so the saved
  module lost it. The knob then went straight into the opcode (0..127) instead
  of through the mapping table → LFO frequency much higher than intended
- Fixed: `mappingTable` is now saved and restored
- If you have an old saved module: load it, re-assign `mappingTable` on the
  relevant knob (`set <id> mappingTable <name>`), and re-save

**Loading a module resets the DSP body**:
- Cause: `syncFromModule()` was called after `restoreModuleFromData()` and
  overwrote `editor.value` with the model template
- Fixed: `TerminalPanel._cmdLoad` and `Toolbar._onLoad` no longer call
  `syncFromModule()` after loading

Can't type `0` in editor inputs:
- Fixed: keyboard shortcuts now skip when focus is in an `<input>` or `<textarea>`
- If it happens again, check `EditorApp.setupEvents()` for `preventDefault()` calls

Editor layout reset:
- `localStorage.removeItem('csmodular:editor-layout')`

Grid settings reset:
- `localStorage.removeItem('csmodular.theme')` — resets theme including `settings.grid`

Modules don't drag correctly on macOS Retina (dpr > 1):
- Known issue. `resizeCanvasToWindow` temporarily uses `dpr = 1` as a workaround.
- See TODO.md → Grid system → HiDPI.

**MIDI not received in browser**:
- Check the console for `[MidiManager]` messages
- Ensure the page is served from `localhost` or `https://`
- On Linux: verify the device is visible in `aconnect -i -o` (ALSA sequencer);
  Chrome/Firefox receive MIDI through ALSA
- On Firefox: Web MIDI may require `dom.webmidi.enabled` in `about:config`
  (usually enabled by default in recent versions)
- Check that no other process (DAW, `aseqdump`) has exclusive access to the port

**MIDI works before recompile but not after**:
- Known `@csound/browser` issue — see the **MIDI** section → *Known issue*

**Oscilloscope shows only zeros / a tiny blip on the left**:
- Cause: `phasor` frequency was too small (`1/4096`), so the index did not
  advance in k-rate/audio-rate and `tablew` overwrote the same slot.
- Fixed: frequency is now `(sr / ksmps) / 4096` (≈ 2.93 Hz at 48 kHz),
  which advances the index reliably.
- If it happens again: check `CsoundGenerator._generateScopeCode()` — the
  `phasor` argument must be a k-rate expression, not a bare constant.

**Oscilloscope channel has no waveform after adding**:
- The ORC must be regenerated — `Send to Scope` triggers `_recompileDebounced()`.
  Wait ~300 ms and check again.
- Check `modularSystem.csoundEngine.getScopeBuffer(cableId)` in the console:
  if `null`, polling is not running; if filled with zeros, `tablew` is not
  writing — inspect the generated ORC (`modularSystem.csoundGen.generateOrc()`)
  for `giScope_<N>` and `tablew` lines.
